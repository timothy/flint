Flint on M4 Max

Recursive released Flint on October 21, 2026: an open-weights coding model built to run on a laptop. This page proposes how to run it on your MacBook Pro: which engine serves it, which harness drives it, how the 64 GB gets spent, and what to check before you rely on it.

  • 256 experts, 6 + 1 shared per token

Harness

Pi

Recursive's recommended local harness, with the smallest prompt to re-read each session. OpenCode is the backup. Claude Code stays on Claude models.

Budget

131,072-token window · 32,768 output · one agent

About 26 GiB of your 64 GB, leaving plenty for your editor, browser and other apps.

Boundary

Loopback only, 127.0.0.1

Nothing leaves the Mac unless you hand a task to Claude Code. Skip the free hosted Flint tiers for work code.

How the pieces connect

You steer Pi. Pi sends the conversation to a model server on this Mac and runs the resulting tool calls in your files. The server runs Flint on the GPU, straight out of unified memory.

Engines swap without touching the loop

rec and Ollama both expose OpenAI-style Chat Completions on localhost. Moving between them changes three values in Pi: base URL, model ID and key.

One agent at a time

rec serves one generation at a time and answers overlapping requests with HTTP 429. Ollama queues them instead. Plan on serial work, not parallel subagents.

Reasoning goes back in

Flint reasons on every turn. Leave effort settings unset, and make sure each assistant message goes back to the server with its reasoning_content.

Where a turn's time goes

Each turn has two costs: reading the new part of the prompt (prefill) and writing the reply (decode). The KV cache decides how much of the prompt has to be read again.

  • Lean harness prompts pay off

    The system prompt and tool schemas are read in full at the start of every session and after every compaction. Pi keeps both small, which is why Recursive recommends it. Informal reports put it at about 1.5× faster workflows than OpenCode.

  • Keep history append-only

    Send reasoning_content back, keep timestamps and git status out of the system prompt, and don't edit earlier messages. Flint's sliding-window layers make mid-history changes costly: an engine that can only rewind to saved checkpoints may read the whole session again.

  • One session per task

    Generation slows as the context grows, because every new token attends over more cache. Compaction rewrites history, which costs a full re-read. A new session for each task keeps both costs small.

Which harness

Use Pi. Recursive tests Flint with it and names it the recommended harness for local coding. rec and Ollama can both launch it already configured, and its small prompt means fewer tokens to read each session on a laptop GPU.

Guardrails for Pi

Pi runs commands without asking. Give each task its own git worktree, review the diff before you merge, start Pi from a shell with no production credentials, and add a permission-gate extension or a container for code you don't trust.

When to hand off

If Flint misses the same task twice, give it to Claude Code on a Claude model. Keep project rules in AGENTS.md and add a one-line CLAUDE.md containing @AGENTS.md, so both harnesses read the same rules.

16-bit cache. Only Flint's 14 full-attention layers grow with context: 4 KV heads × 128 dims × 2 (keys and values) × 2 bytes × 14 layers is 28 KiB per token. The 35 sliding-window layers keep 513 tokens each and add almost nothing.

Disk

Each engine keeps its own copy of the weights: about 30 GB for rec with its runtime, 23 GB for Ollama, 25.1 GB for the llama.cpp Q4 file. With 110 GB free, keep one copy at a time and skip the 80 GB BF16 checkpoint.

Power

Plug in for long agent sessions; sustained GPU load can throttle a laptop. Use High Power mode in Battery settings if this Mac offers it.

Build plan

Six steps, each with a check that proves it worked before you move on.

  1. Find out whether rec runs here

    rec is Recursive's own engine and the fastest option, but its docs don't list the M4 Max. The installer answers the question: after downloading, it runs rec doctor and stops if this Mac isn't supported. It also adds ~/.local/bin to your PATH in ~/.zshrc.

    zsh
    curl -fsSL https://raw.githubusercontent.com/recursive-oss/rec/main/install.sh | bash

    If it passes, launch from your repo and skip to step 4. rec downloads Flint, starts its server on port 11500 and keeps it running after Pi exits; stop it with rec stop.

    zsh
    cd ~/apps/your-repo
rec launch pi

    Done when rec doctor has passed or refused. If it refused, delete ~/.local/share/rec if the folder was left behind, and go to step 2.

  2. Serve Flint with Ollama

    Install the Ollama app from ollama.com/download; you need a version that includes ollama launch. Set the server options, then quit and reopen Ollama so it reads them. launchctl values last until you restart the Mac.

    zsh
    launchctl setenv OLLAMA_CONTEXT_LENGTH 131072
launchctl setenv OLLAMA_NUM_PARALLEL 1
launchctl setenv OLLAMA_KEEP_ALIVE 30m
ollama pull flint:40b-a2b-qat-int4

    Done when curl -s http://127.0.0.1:11434/v1/models lists flint:40b-a2b-qat-int4.

  3. Launch Pi on Flint

    zsh
    npm install -g --ignore-scripts @earendil-works/pi-coding-agent
cd ~/apps/your-repo
ollama launch pi

    Pick flint:40b-a2b-qat-int4 when asked; Ollama writes Pi's provider settings for you. In a second terminal, ollama ps should show the model on 100% GPU with a 131072 context.

    Done when Pi answers “What is 19 + 23?” with 42.

  4. Run Recursive's tool-cycle check

    In a throwaway folder, create smoke-input.txt containing 19 23. Ask Pi to read it with its file tool, add the numbers, write 42 and a newline to result.txt, check the file with a shell command, and report back. Then check it yourself:

    zsh
    python3 -c 'from pathlib import Path; assert Path("result.txt").read_bytes() == b"42\n"'

    Done when you saw a read-tool call, Pi's own check passed, and the command above exits without an error. Note the elapsed time and any retries.

  5. Add guardrails and shared rules

    Write project rules in AGENTS.md and add a CLAUDE.md containing @AGENTS.md. Run each Flint task in its own worktree, from a shell with no production credentials.

    zsh
    git worktree add ../your-repo-flint -b flint/first-task
cd ../your-repo-flint
ollama launch pi

    Done when one real task has gone from worktree to a reviewed, merged diff.

  6. Measure, then tune

    Time three real tasks at the 128k window. For a quick probe, ollama run flint:40b-a2b-qat-int4 --verbose prints prompt and generation speed. If long sessions slow down, start new sessions sooner before you shrink the window.

    Optional: compare llama.cpp

    Flint support landed in upstream llama.cpp on October 21, 2026 (PR #30928). Make sure your build is at least that new; if Homebrew's isn't, use a release from github.com/ggml-org/llama.cpp.

    zsh
    brew install llama.cpp
llama-server --version
    zsh
    llama-server -hf unsloth/flint-GGUF:UD-Q4_K_XL \
  --alias flint-local --host 127.0.0.1 --port 8080 \
  --ctx-size 131072 --parallel 1 --n-gpu-layers 99 \
  --jinja --temp 1.0 --top-p 0.95 --top-k 20 --metrics

    UD-Q4_K_XL is a 25.1 GB download. UD-Q6_K_XL (36.3 GB) also fits if you want to compare tool-call quality. Merge this provider into Pi's config, keeping any providers already there:

    ~/.pi/agent/models.json
    {
  "providers": {
    "local-flint": {
      "baseUrl": "http://127.0.0.1:8080/v1",
      "api": "openai-completions",
      "apiKey": "${LOCAL_API_KEY}",
      "models": [{
        "id": "flint-local",
        "name": "Flint (local)",
        "reasoning": false,
        "input": ["text"],
        "contextWindow": 131072,
        "maxTokens": 32768,
        "compat": { "maxTokensField": "max_tokens" }
      }]
    }
  }
}
    zsh
    LOCAL_API_KEY=local pi --provider local-flint --model flint-local

    "reasoning": false only hides Pi's thinking controls; Flint still reasons. If the server log says it is forcing full prompt re-processing, the history changed somewhere the cache can't rewind to.

    Done when you've picked the engine, quantization and window from your own numbers.

Risks and open questions

  • Engine

    rec may refuse this Mac. The rec page lists M4 Pro, M5 Pro and M5 Max, while the Mac recipe and troubleshooting pages say “M4 or M5 Pro or Max”. One rec doctor run settles it.

  • Maturity

    Everything here is days old. Flint shipped October 21, 2026, and llama.cpp support merged the same day with a stopgap its author says costs 10–30% in speed. Once a setup works, pin the versions.

  • Speed

    No M4 Max numbers exist yet. Recursive reports rec above 125 tok/s averaged over a 128k-token session on an M4 Pro, and 1.4–2.6× faster than llama.cpp across 1K–252K prompts. Your own measurements are the source of truth.

  • Quality

    Quantizations aren't interchangeable. Recursive's 4-bit builds are trained for quantization; their NVFP4 build lands within 0.7 points of 16-bit. Community GGUFs are converted separately. If tool calls misfire on llama.cpp, compare a 6-bit file before blaming the model.

  • Safety

    Pi doesn't ask before running commands. Worktrees, a clean shell and an approval extension keep mistakes contained.

  • Privacy

    The free hosted Flint options aren't private. Pi labels Radius “free, trains on data”, and OpenCode's free tier doesn't state its data terms. Keep work code on the local path.
